### **Step 1: Set up connection details**
```python
import requests
from requests.auth import HTTPBasicAuth
import json

# Replace with your ServiceNow instance details
instance = 'your_instance'  # e.g., 'dev12345'

    "Accept": "application/json",
    "Content-Type": "application/json"
}
```

---

### **Step 2: Send the GET request**
```python
response = requests.get(url, auth=HTTPBasicAuth(username, password), headers=headers)

    for record in data['result']:
        print(record)
else:
    print(f"Failed to fetch data. Status code: {response.status_code}")
    print(response.text)
```

To connect **Databricks** to **Datadog**, you typically need to use **Datadog's API** and send HTTP requests. You can use the following Python code to simply establish that connection, authenticate, and check the status of the connection:

### **Code to Connect Databricks to Datadog**

```python
import requests

# Replace with your Datadog API key
api_key = "your_datadog_api_key"

# Datadog API URL (for checking status or interacting with APIs)
url = "https://api.datadoghq.com/api/v1/validate"

# Headers with API Key for authentication
headers = {
    "DD-API-KEY": api_key,
    "Content-Type": "application/json"
}

# Send a GET request to validate the API key and connection
response = requests.get(url, headers=headers)

# Check if the connection is successful (HTTP 200)
if response.status_code == 200:
    print("Successfully connected to Datadog!")
else:
    print(f"Failed to connect. Status code: {response.status_code}")
    print(response.text)
```

### **Explanation:**
- **Datadog API Key:** You'll use your Datadog API key to authenticate. This key should be securely stored (e.g., using **Databricks Secrets**).
- **Validation Endpoint:** We're using the **`/api/v1/validate`** endpoint to simply check if your API key is valid and if Databricks can successfully communicate with Datadog.
- **Response Check:** If the connection is successful (status code 200), you'll see a success message. If there’s an error, the status code and message will help diagnose the issue.

Sening logs and metrics to the Datadog _--------------
Great! Now that you have the basic connection to **Datadog**, let's proceed with sending **logs** and **metrics** from **Azure Databricks** to **Datadog**.

### **Step-by-Step: Sending Logs and Metrics from Databricks to Datadog**

#### **1. Sending Logs to Datadog**

Here’s how you can send logs using **Datadog’s Logs API**.

```python
import requests
import json
import datetime

# Fetching API key securely from Databricks secrets
api_key = dbutils.secrets.get(scope="datadog-secrets", key="api_key")

# Datadog log intake URL
log_url = "https://http-intake.logs.datadoghq.com/v1/input"

# Sample log payload
log_data = {
    "message": "ETL job completed successfully in Azure Databricks",
    "ddsource": "databricks",
    "service": "my-etl-service",
    "hostname": "databricks-cluster",
    "status": "info",
    "timestamp": int(datetime.datetime.utcnow().timestamp())  # current timestamp
}

# Headers with Datadog API Key
headers = {
    "Content-Type": "application/json",
    "DD-API-KEY": api_key
}

# Send log to Datadog
response = requests.post(log_url, headers=headers, data=json.dumps(log_data))

if response.status_code == 200:
    print("Log sent successfully to Datadog!")
else:
    print(f"Failed to send log. Status: {response.status_code}")
    print(response.text)
```

#### **Explanation of Log Code:**
- The **`message`** contains the actual log message.
- **`ddsource`** identifies the source (e.g., `databricks`).
- **`service`** groups logs by service (e.g., `my-etl-service`).
- **`timestamp`** is the current time (in Unix timestamp format).

This sends a simple log to **Datadog Logs**.

---

#### **2. Sending Metrics to Datadog**

Here’s how to send **custom metrics** using **Datadog’s Metrics API**.

```python
# Datadog Metrics API endpoint
metric_url = f"https://api.datadoghq.com/api/v1/series?api_key={api_key}"

# Sample metric data (you can customize this)
metric_data = {
    "series": [
        {
            "metric": "databricks.job.runtime.seconds",
            "points": [[int(datetime.datetime.utcnow().timestamp()), 90]],  # Timestamp and value
            "type": "gauge",  # Type of metric (gauge, count, etc.)
            "tags": ["env:prod", "team:dataengineering"],
            "host": "databricks-cluster"
        }
    ]
}

# Send metrics to Datadog
metric_response = requests.post(metric_url, headers={"Content-Type": "application/json"}, data=json.dumps(metric_data))

if metric_response.status_code == 202:
    print("Metric sent successfully to Datadog!")
else:
    print(f"Failed to send metric. Status: {metric_response.status_code}")
    print(metric_response.text)
```

#### **Explanation of Metrics Code:**
- **`metric`** is the name of the metric (e.g., `databricks.job.runtime.seconds`).
- **`points`** contains the timestamp (in Unix format) and the value of the metric (e.g., `90` seconds).
- **`type`** indicates the type of metric (e.g., **gauge** or **count**).
- **`tags`** are additional labels that help to categorize and filter metrics (e.g., `env:prod`, `team:dataengineering`).
- **`host`** is the host identifier (e.g., the Databricks cluster name).

### **Putting It All Together:**

Now, you have both the **logs** and **metrics** code to send data from **Azure Databricks** to **Datadog**. Here’s a complete example:

```python
import requests
import json

    "series": [
        {
            "metric": "databricks.job.runtime.seconds",

            "host": "databricks-cluster"
        }
    ]
}
metric_response = requests.post(metric_url, headers={"Content-Type": "application/json"}, data=json.dumps(metric_data))

if metric_response.status_code == 202:

else:
    print(f"Failed to send metric. Status: {metric_response.status_code}")
    print(metric_response.text)
```
